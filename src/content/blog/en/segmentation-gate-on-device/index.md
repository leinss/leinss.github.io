Thai does not put spaces between words. A reader who knows the language segments a sentence without noticing it happen, but a program has to guess, and every feature downstream of that guess inherits it. So the word segmenter in the Thai reading tutor I built for myself is gated in CI, and the headline number for that gate is a boundary F1 of 0.9845 over a 399-entry golden set.

That number is the weakest of the five things the gate asserts, and the reason is the part worth writing down.

240 of the 399 entries are single words. They carry no boundary at all, so entry count is the wrong guard and the aggregate silently averages over the cases that are hard.

The entries where two reference segmenters disagreed and a human had to decide are about five percent of the boundaries in the set. A regression that ate every one of those and left the easy ones untouched would move F1 by a rounding error and go green.

## Five floors, not one

The test asserts a contract F1 of 0.92, which is the number a competing implementation would have to beat to be considered correct at all. Above it sits a drift floor of 0.97, set well clear of the contract so that a slow decline is caught while it is still slow. Exact whole-string matches must stay at or above 385 of 399; today it is 390.

The golden set itself must contain at least 300 reference boundaries, so regenerating it into something easier fails rather than passes. And the adjudicated group has to keep at least 7 exact matches on its own, because that is the only floor the aggregate cannot drown.

Boundaries, not tokens, and certainly not accuracy. Accuracy needs a denominator of things that can be right or wrong, and for segmentation the honest unit is the gap between two characters: cut, or do not cut.

Score whole tokens and a sentence with nine of ten boundaries correct can end up indistinguishable from one with none, because a single missed cut corrupts both tokens it sits between. Micro-averaged over boundaries, the partial credit lands where it belongs.

The segmenter itself is unremarkable and that is deliberate. It is a Viterbi decode over a 60,941-word lexicon with a per-word penalty, a shortest-cost path through the string, no model involved. A lexicon ablation is in the repo: cutting down to a smaller attested-and-short word list kept none of twelve test compounds whole, and the full headword set kept all twelve.

There is a Python twin of the decoder and a test that enforces parity between the two, because the content pipeline runs in Python at build time and the app runs TypeScript at read time, and two implementations of a cost model drift.

## The golden set never imports the code it grades

Its boundaries come from the consensus of two independent reference segmenters, or from a recorded human adjudication when those two disagree. The builder hard-fails on an un-adjudicated disagreement rather than picking a side. This is the whole reason the number means anything: a golden set generated by the thing under test measures self-consistency and reports it in exactly the same tone as it would report correctness.

## The model runs on the phone

Qwen2.5 3B Instruct, Q4_K_M, about 2.0 GB, loaded through llama.rn with a 4096-token context and an output budget of 1600. Temperature 0.3. Structured output is a JSON Schema passed with `strict: true`, which the runtime compiles into a GBNF grammar, so the decoder is only ever offered tokens the schema permits. Unparseable JSON stops being a failure mode. Nothing else does.

A grammar constrains shape and says nothing about truth. The model will happily emit a schema-perfect annotation for a word that is not in the sentence it was given, and that is the failure that actually shows up on screen. So every reply is checked back against the source text before it is used. If nothing survives that check, the reply is discarded whole.

## What runs when the model is wrong

Underneath the model sits a deterministic path built on the curriculum spine, a 4,664-item ordered list mapping each word to the chapter that introduces it. Given a sentence, it segments, looks each word up, and returns an annotation with no inference anywhere in it. It is worse than the model. It is always available, always the same, and it cannot invent a word.

It takes over on three triggers: any model error other than the learner cancelling, a reply that keeps nothing when matched against the source, and the learner pressing Stop.

The rule that took the longest to get right is about the cache. A page with at least one model-annotated sentence is cached; a fully deterministic page is not. Without that, one flaky load would freeze the degraded result into the reading history and the page would never be re-annotated, which reads as "the app got worse and stayed worse" and is nearly impossible to report as a bug.

## The repetition invariant

The spaced-repetition scheduler is a Leitner ladder with intervals of 0, 1, 3, 7, 16 and 40 days. Two properties hold it up. Coverage: every item a lesson introduces is covered by a card in the deck. Resurfacing: no scheduler state parks a card forever, because the top box is 40 days and there is no retired state, so an item answered correctly every single time still comes back.

Neither is proved. They are asserted by a test that walks the real shipped catalog item by item rather than a fixture, and the argument for that is short: a hand-built fixture proves the function, and only the real data proves the curriculum has no hole in it.

It found one immediately. 539 catalog items were collapsing into 402 cards, and 137 ids had no card at all, so the coverage property was false in production data while every unit test around the scheduler passed.

## The numbers that are not here

No tokens per second. The app carries a timing ring over the last 50 model calls and reports prefill and decode rates on a debug screen, but no run of it is committed, so there is nothing to quote and quoting the comment in the source instead would be quoting a bug report from before nine defects in that path were fixed.

No coverage percentage either; there is no coverage threshold configured and inventing one after the fact is not a measurement. What exists is 1,406 unit tests across 111 suites, 16 Maestro UI flows, and 52 merged pull requests since late July.

## Why it is not a product

The content pipeline is built from copyrighted textbooks. Word lists and short example sentences are harvested into the spine; illustrations are not extracted and must not be.

That line is defensible for a tool one person uses and it is not defensible for a public listing, so the app ships to a Play internal test track with a single tester on it and will not be listed. The source PDFs are not in the repository and CI cannot run the content checks that need them.
